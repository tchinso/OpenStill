# SelectorX 1.6.2 개선 기록

SelectorX는 OpenStill에서 독자적으로 작성한 선택자 엔진입니다. 1.6.2에서도 조상 경로와 이전 형제의 근거를 수집하고, 실제 DOM에서 검증하며 선택자를 줄이는 기존 구조를 유지합니다. 상업용 프로그램인 `References/`의 구현은 기능과 판단 원칙을 비교하는 자료로 읽었으며, 제품 코드를 가져오거나 SelectorX를 교체하지 않았습니다.

## 확인한 원인

`https://xhcyv.com/threads/by-category/art`의 실제 목록 DOM에서 아래 선택자는 요소와 일치했습니다.

```css
article:first-child [class*='inset']
article:nth-child(2) [class*='inset']
article:nth-child(3) [class*='inset']
```

일치한 요소는 게시글 카드 전체를 덮는 빈 링크였습니다. `absolute inset-0` 등의 클래스가 붙은 `<a>`에는 게시글 주소와 `aria-label`·`title`이 있었지만 텍스트 자식은 없었습니다. 화면에 보이는 제목은 링크의 형제 요소였습니다. 따라서 선택자는 요소를 찾았어도 `{ "type": "text" }`로 추출하면 제목이 나오지 않았습니다.

이는 선택자 문법보다 앞선 **클릭 대상 결정과 캡처 필드의 문제**입니다. 실제 제목 위를 클릭해도 포인터 이벤트를 받는 빈 링크를 저장했고, 빈 텍스트 결과를 제목으로 기대했습니다. 여기에 `:first-child`·`:nth-child()`는 전체 형제 순서에 의존하므로 목록 앞에 새 요소가 추가되면 다른 카드를 가리킬 수 있습니다.

## References와 비교한 내용

| 비교 대상 | 확인 결과와 1.6.2의 판단 |
| --- | --- |
| 클릭한 요소 | References도 이벤트의 첫 요소를 그대로 선택합니다. 이번 빈 오버레이 문제를 자동으로 해결하는 기능은 확인되지 않았습니다. OpenStill은 일반적인 오버레이를 판별하고 클릭 위치의 읽을 수 있는 형제 내용을 선택하도록 개선했습니다. |
| 선택자 근거 순위 | References는 CSS·레이아웃 용어를 의미 있는 근거보다 낮게 평가합니다. 이 원칙을 SelectorX의 자체 점수 계산에 반영해 레이아웃 근거의 순위를 낮췄습니다. 필요한 근거는 후보에서 제거하지 않습니다. |
| 일치 결과와 필드 | 일치 개수와 선택 가능한 속성을 보여 주는 원칙이 유용합니다. OpenStill에는 이미 여러 캡처 필드가 있으며, 이번에는 미리보기가 실제 설정한 필드 값을 표시하도록 맞췄습니다. |
| 변경되는 값 제외 | 게시글 주소·제목·접근성 이름을 선택자 값으로 고정하면 새 게시글을 놓칠 수 있습니다. OpenStill도 이미 `href`, `title`, `aria-label` 등의 값은 자동 선택자의 근거에서 제외합니다. 캡처 필드로 읽는 것과 선택자에 고정하는 것은 별개입니다. |
| 선택 영역 확장·축소 | References는 부모 영역으로 확장하고 원래 클릭 경로로 축소하는 UI가 있습니다. 이 원칙을 자체 구현해 **상위 영역**·**하위 영역**으로 선택 범위를 조정하고 원래 선택 경로로 돌아가도록 했습니다. |
| 반복 목록 선택 | References의 선택·제외·유사 요소 개념이 유용합니다. **유사 요소 함께 선택**을 누르면 가까운 반복 항목들의 같은 위치에 있는 요소를 찾고, 자체 SelectorX가 여러 대상을 하나의 규칙으로 생성합니다. 현재 DOM에서 실제 일치 집합을 검증한 후 적용하며, 사용자가 요청할 때만 목록 선택으로 바꿉니다. |

CSS/XCSS/XPath 생성, Shadow DOM 탐색, DOM 기반 검증, 여러 대상을 받는 선택자 생성, 선택·제외·유사 요소 API, 위치 선택자 안내, 속성·프로퍼티 필드는 기존 SelectorX와 picker의 자체 기능입니다. 해당 기능을 다시 가져올 필요는 없었으며, 반복 목록 UI도 기존의 자체 엔진을 사용합니다.

## 선택과 미리보기의 변화

빈 오버레이 아래의 내용을 안전하게 특정할 수 있으면 그 내용을 선택합니다. 새로 선택한 요소에 텍스트가 없는 경우에는 비어 있지 않은 `aria-label`, `title`, `alt` 중 첫 속성을 기본 캡처 필드로 사용합니다. 기존 저장된 선택자의 필드는 자동 변경하지 않으며 기존 캡처 계약도 유지합니다.

미리보기에는 설정한 텍스트·속성·프로퍼티의 실제 값을 표시합니다. `href` 값과 프로퍼티의 `0`·`false`도 누락하지 않습니다. 요소는 일치하지만 설정한 필드가 비어 있으면 빈 결과 안내를 표시합니다. 기존 일치 개수와 위치 선택자 안내도 함께 유지합니다.

새 게시글을 받으려는 경우 제목 하나를 선택한 뒤 **유사 요소 함께 선택**으로 제목 목록을 하나의 규칙에 담을 수 있습니다. 세 개의 `:nth-child()` 규칙을 수동으로 저장할 필요가 줄어듭니다. 현재 목록의 검증은 향후 사이트 구조 변경까지 보장하지 않으므로, 일치 결과와 위치 의존 안내를 확인해 목록의 범위를 정해야 합니다.

제목을 선택해도 같은 카드의 빈 링크에 있는 `aria-label`·`title`과 제목이 정확히 일치하고 HTTP(S) 주소가 하나로 확정되면 게시글 식별자로 유지합니다. 같은 제목의 다른 글도 URL로 구분합니다. 작성자 링크, 중첩 카드, 모호한 여러 주소, 명시적으로 제외한 링크·속성은 식별자 추정에 사용하지 않습니다.

## 로그인과 실행 환경

이번 목록 DOM 확인에는 사용자가 로그인했다고 알려 준 Codex 인앱 브라우저를 사용했습니다. 확인 당시 페이지에는 로그인 메뉴도 표시되어 인증된 세션인지는 확정하지 않았습니다. 목록과 빈 오버레이 링크의 DOM은 확인했습니다.

OpenStill의 실제 확인은 확장을 설치한 Chrome 프로필의 전용 탭에서 실행됩니다. Codex 인앱 브라우저와 Chrome의 로그인 세션은 별개이므로, 로그인이 필요한 페이지는 해당 Chrome 프로필에서도 로그인해야 합니다. 로그인 화면 때문에 대상 DOM이 없는 경우와, 대상 요소는 있지만 선택한 필드가 비어 있는 경우를 구분해야 합니다.

로그인·사이트 변경이 필요한 페이지의 결과는 해당 Chrome 세션과 캡처 시점의 DOM에 달려 있습니다. 특정 사이트의 선택자를 하드코딩하거나 브라우저 간 인증 정보를 옮기는 처리는 추가하지 않았습니다.

## 검증

2026-10-06, 기존 검사와 새 회귀 검사를 합쳐 173개를 확인했으며 모두 통과했습니다. 실제 Chrome에서 마우스 선택과 영역 조절, 새 카드 추가 후 제목 목록 수집, 작은 아이콘·모달 경계, Shadow DOM, 필드 미리보기와 캡처 일치, 중복 제목의 URL 식별을 검사했습니다. 실제 unpacked 확장 로드와 runtime 메시지 검사도 임시 Edge 프로필에서 통과했습니다. 선택 페이지의 원본 DOM에는 검증 스크립트를 주입하지 않았으며 해당 사이트 전체의 예약 운영은 별도입니다.

관련 코드 변경의 영향을 받지 않는 검증 결과는 재사용했고, 후속 수정이 영향을 줄 수 있는 캡처·선택기 검사는 최종 소스에서 다시 실행했습니다. 최종 집계에는 실행 환경 설정 때문에 처음 생략된 확장 검사를 설정 후 실제 통과한 결과로 대체했으며, 생략된 검사를 통과로 계산하지 않았습니다.
